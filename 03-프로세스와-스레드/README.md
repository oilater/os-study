## 요약

- **프로그램 vs 프로세스**: 저장장치에 있는 정적인 프로그램이 메모리에 올라와 실행되면 동적인 프로세스가 된다.
- **PCB**: 프로세스를 관리하기 위한 작업 지시서. PID, 메모리 정보, 프로그램 카운터·레지스터 같은 중간값을 담는다.
- **프로세스 = 프로그램 + PCB**: PCB를 받으면 프로세스가 되고, PCB가 폐기되면 종료된다.
- **다섯 가지 상태**: 생성 → 준비 ⇄ 실행 → 완료, 실행 중 입출력을 요청하면 대기 → 준비
- **상태 전환 작업**: dispatch(준비 → 실행), timeout(실행 → 준비), block(실행 → 대기), wakeup(대기 → 준비), exit(실행 → 완료)
- **휴식 vs 보류**: 휴식은 메모리에 있는 채로 멈춘 상태, 보류는 메모리에서 스왑 영역으로 쫓겨난 상태
- **PCB의 구성**: 포인터, 상태, PID, 프로그램 카운터, 우선순위, 레지스터, 메모리·자원·계정 정보, PPID·CPID
- **대기 큐**: 같은 입출력을 기다리는 PCB끼리 포인터로 연결해 모아 둔다.
- **문맥 교환**: 나가는 프로세스의 상태를 PCB에 저장하고, 들어오는 프로세스의 PCB 값으로 CPU를 다시 세팅하는 것. 타임아웃이나 인터럽트 때 일어난다.
- **프로세스의 구조**: 코드 영역(읽기 전용), 데이터 영역(변수·파일), 스택 영역(함수 복귀 주소 등)
- **fork() / exec()**: fork()는 실행 중인 프로세스를 복사하고, exec()는 프로세스 구조는 그대로 둔 채 내용만 새 프로그램으로 바꾼다.
- **프로세스 계층 구조**: 모든 프로세스는 init을 뿌리로 하는 트리를 이루며, 자식이 끝나면 부모가 자원을 회수한다.
- **고아 / 좀비 프로세스**: 부모가 먼저 끝나면 고아, 자식이 끝났는데 부모가 정리하지 않으면 좀비

## 느낀 점

- CPU 스케줄러와 프로세스의 상태(활성 상태, 휴식·보류 같은 특별한 상태) 개념을 소프트웨어 설계에도 적용해볼 수 있겠다는 생각이 들었다.
- 이런 개념을 제대로 활용하려면 자료구조와 알고리즘을 확실히 이해해야겠다는 필요성을 느꼈다.
- 인터럽트가 입출력뿐 아니라 메모리 범위를 벗어나는 것 같은 이벤트에 의해서도 발생한다는 걸 알았다.
